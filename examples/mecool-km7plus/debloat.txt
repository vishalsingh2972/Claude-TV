# Known quirks on this firmware:
# - HOME: launcherx declares HOME at priority 2 and com.google.android.tungsten.setupwraith/.RecoveryActivity
#   at priority 1, so set-home-activity reports Success but Home keeps opening the stock launcher.
#   Disabling only launcherx sends Home to the setupwraith Recovery screen; on our unit ADB then dropped
#   and the screen went black until the box came back. Shell cannot disable the RecoveryActivity component
#   on Android 14 (SecurityException). What worked: disable setupwraith FIRST, then launcherx, then
#   set-home-activity com.gathin.tvhome/.MainActivity. Keep both lines below together.
# - First `pm install` failed with INSTALL_FAILED_VERIFICATION_FAILURE. Temporarily
#   `settings put global verifier_verify_adb_installs 0`, install, then
#   `settings delete global verifier_verify_adb_installs` to restore the default.
# - dreamx is the active screensaver. Switch first, e.g.
#   tools/tv.py 'settings put secure screensaver_components com.gathin.tvhome/.ClockDream'
# - ADB TCP port 5555 came from service.adb.tcp.port (not persist.*), so after a reboot USB debugging
#   alone may not reopen it; look for a network debugging toggle in Developer options.
# - Leave alone: com.droidlogic.* (Amlogic HDMI/system), com.dolby.android.audio.service,
#   com.mft.rcupair (remote pairing), com.sdt.globalkey / com.sdt.vendor (remote keys),
#   com.google.android.tv.dfuservice (remote firmware, find-my-remote), com.google.android.tv.axel,
#   com.google.android.tv.remote.service, com.sdt.ota / com.sdt.upgrade (system updates),
#   com.mft.frontpanelledsservice (front LED), com.oemservice (enabled accessibility service that
#   detects remote keys), com.oem.qa (has a KeyDefinition screen; purpose unclear, kept and only hidden).
# - Verified after applying: YouTube launches, Home returns to Claude TV, Gboard stays default IME,
#   com.oemservice accessibility service stays enabled. Physical remote buttons not tested.
